# Отчёт по аудиту безопасности

project_code: profiles-s01

## Область проверки
- Проверялись сервисы: REST, gRPC, GraphQL и конфигурация gateway.
- Метод: ручной аудит по чек-листу + несколько негативных (атакующих) запросов.

## Найденные проблемы

1. Слабая валидация входных данных в нескольких обработчиках создания и обновления.
   - Риск: высокий.
   - Влияние: возможны некорректные данные в базе и дополнительные векторы инъекций.
   - Рекомендация: ввести строгую схему валидации и отклонять неизвестные/лишние поля.

2. Нет явного ограничения частоты запросов к чувствительным endpoint (аутентификация и т.п.).
   - Риск: средний.
   - Влияние: возможен перебор паролей и злоупотребления со стороны ботов.
   - Рекомендация: добавить лимиты по IP/пользователю и временные блокировки при превышении.

3. Неполный набор заголовков безопасности в ответах gateway.
   - Риск: средний.
   - Влияние: расширенная поверхность атак в браузере.
   - Рекомендация: добавить HSTS, X-Frame-Options, X-Content-Type-Options, Content-Security-Policy.

4. Логи могут содержать части тела запроса с чувствительными полями.
   - Риск: средний.
   - Влияние: утечка персональных данных через систему логирования.
   - Рекомендация: маскировать или удалять чувствительные поля перед записью в логи.

## Положительные моменты
- Есть базовые endpoint для проверки состояния сервиса (health-check), это помогает мониторингу.
- Разделение функциональности на отдельные сервисы уменьшает зону поражения по сравнению с монолитом.

## Итоговая оценка
Текущий уровень безопасности можно считать умеренным: в ходе аудита не найдено
подтверждённых критических уязвимостей, но несколько средних и высоких рисков
нужно устранить до выхода системы в production.
